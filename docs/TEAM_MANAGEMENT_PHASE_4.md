## A. Existing start/sit architecture (the control)

Inspected in the repo — not assumed from prior discussion.

### A.1 Projection source
- **`SleeperWeeklyProjectionProvider`** (`lib/weekly/projections/sleeper-weekly.ts`,
  `sleeper-weekly-rotowire`). Sleeper's per-week projection feed (`/projections/nfl/{season}/{week}`,
  RotoWire-backed) → real projected **stat lines** → scored with the **league's own canonical
  scoring** (`scoreWeeklyLine`, `lib/weekly/scoring.ts`). Sleeper's precomputed `pts_*` are
  **not** trusted for offense.
- K / D-ST: the weekly feed omits XP (K) and sacks/points-allowed (DST) → those two slots fall
  back to Sleeper `pts_std`, flagged LOW/MEDIUM. Certified separately; **out of scope to
  destabilize** (spec §17, §42).
- `projected_points` is `null` (never `0`) when missing. Schedule-proven bye → real `0` with
  `projection_status: "bye"`.
- The provider is a seam (`ProjectionProvider` interface, `getWeeklyProjectionProvider`).
  A league's own Roster-Intel weekly projections would slot in with no analytics change — they
  do not exist yet.
- **Opponent awareness today:** implicit only. RotoWire analysts set weekly numbers knowing
  the matchup, but there is **no explicit NFL-defense-strength model in the weekly path**.
  `opponent` and `is_home` are carried on `WeeklyProjection` but nothing in the weekly engine
  adjusts a projection by opponent.

### A.2 Rest-of-season signal (`lib/weekly/projections-ri.ts`)
`RosterIntelSeasonSignalProvider` — the repo's season model (`ri-structural-2026.3`) consumed
**ordinally** (position rank, VOR, tier) + as a disagreement/confidence signal vs the external
season projection. Never numerically ensembled. Not a weekly projection.

### A.3 Uncertainty (`lib/weekly/uncertainty.ts`)
- `weeklyBand(median, position, expectedAvailability)` → floor/ceiling from a documented
  per-position weekly **coefficient of variation** (`WEEKLY_POSITION_CV`: QB .33, RB .44,
  WR .48, TE .52, K .42, DEF .58). `uncertainty_source` flag on every projection:
  `source_distribution | position_volatility_heuristic | none`. Sleeper gives no distribution →
  it is always the heuristic today.
- **No covariance, no correlation, no player-to-player joint distribution.**
- `decisionConfidence({edge, std_dev_a, std_dev_b, incomplete, uncertainty_is_heuristic})` →
  `HIGH | MEDIUM | LOW`. z = |edge| / combined SD, plus an **absolute-edge gate** (a 0.3-pt
  edge between two low-variance players stays LOW). Heuristic SDs cap most outcomes at MEDIUM
  unless the edge is large (≥4.5).

### A.4 Lineup optimizer (`lib/weekly/lineup.ts` → `buildOptimalLineup`)
- **Single objective — MAX_EXPECTED.** Max-weight bipartite matching (`hungarianMaxWeight`)
  over `slots × rostered players`, weight = `projected_points`, ineligible pairs excluded.
- Legality is authoritative via **`maxSlotMatching`** (`lib/weekly/slots.ts:70`) +
  `slotEligiblePositions` / `FLEX_ELIGIBILITY` (Sleeper `FLEX`/`SUPER_FLEX`/`WRRB_FLEX`/…,
  Yahoo `W/R/T`/`Q/W/R/T`/…). Deterministic tie-break: canonical id, then roster order.
- Three projection states kept distinct and never conflated: `KNOWN` / `VERIFIED_ZERO`
  (schedule-proven bye) / `UNKNOWN` (no projection — never a numeric 0). An UNKNOWN in the
  optimal lineup → `optimality_status: "PROVISIONAL"`, distortable totals returned `null`.
- Actionable changes derived from the **starter-set difference**, never per-slot permutations
  (re-ordering RB/WR/FLEX among the same starters is not a move).
- **No MAX_WIN_PROBABILITY / HIGH_CEILING / HIGH_FLOOR / LATE_SWAP_SAFE mode exists.** Those
  names are not in the codebase.

### A.5 Start/sit surface (`lib/weekly/start-sit.ts` → `compareStartSit`)
Pairwise A-vs-B: `projection_edge`, `floor_edge`, `ceiling_edge`, `availability_edge`
(`safer|riskier|neutral`), `replacement_impact` (opportunity cost vs waiver line), `confidence`
(from `decisionConfidence`), `recommendation ∈ {START_A, START_B, TOO_CLOSE,
UNRESOLVED_PROJECTION}`, `reasons[]`. Thresholds: `|edge| ≥ 0.75` + not-LOW → START;
`|edge| ≥ 2.5` always. Generated by `buildCloseCalls` (`lib/weekly/intelligence.ts`) from the
lineup starter-set diff + bench-vs-starter close calls.

### A.6 Matchup analysis (`lib/weekly/matchup.ts`)
My best legal lineup vs the opponent's best legal lineup; margin; positional edges; a **seeded
Monte-Carlo win probability** (20k trials, per-player `Normal(proj, sd)`, **independent draws**,
`win_probability_confidence: "LOW" | "UNAVAILABLE"`, omitted below 70% projection coverage,
explicit `method`). It is post-hoc analysis, **not a lineup objective**, and explicitly "NOT a
spread-to-probability conversion".

### A.7 Injury / role / availability
- `injuryToAvailability(status)` in the Sleeper provider maps `injury_status` → `expected_availability ∈ [0,1]`.
- `lib/weekly/availability.ts` + `lib/weekly/context.ts` carry `injury_status`,
  `expected_availability`, `bye_status` (`VERIFIED|UNVERIFIED` — only from an authoritative
  schedule, never feed absence).
- **No snap-share / role-projection / teammate-absence model in the weekly path.** Role change
  is not modeled beyond the injury flag. (Phase 2 Team-State has structural depth flags but
  Phase 4 must not reach into Team-State — §32.)
- `DataQualityStatus` includes `INJURY_DATA_STALE`, `PLAYER_IDENTITY_UNRESOLVED`,
  `PROJECTIONS_PARTIAL`, `NO_OPPONENT` — the degrade vocabulary already exists.

### A.8 Decision scoring (`lib/weekly/decision-score.ts`)
`buildScore` — transparent weighted component sum (`WEEKLY_WEIGHTS`), used by
waivers/roster-move recommendations. **`compareStartSit` does not use it** — start/sit is its
own comparison object. Good precedent for a decomposed (non-opaque) Phase 4 decision score.

### A.9 Routes / consumers
`app/api/lineup/[league]/[manager]/week/[week]` → `buildOptimalLineup`.
`app/api/intelligence/[league]/[manager]/week/[week]` → `buildWeeklyIntelligence` (includes
`start_sit: StartSitComparison[]`). `app/api/matchup/...`. `buildOptimalLineup` is **also**
reused by the trade engine (`lib/trades/evaluate.ts`, `lib/trades/ros.ts`) — any change to it
is a trade-engine regression risk (§7, §32: do not regress).

### A.10 Existing tests
`test/weekly-lineup.test.ts` (FLEX/SUPERFLEX optimal assignment, RB/WR/FLEX chain pairing,
permutation → 0 changes), `weekly-matchup`, `weekly-hardening`, `weekly-positional-needs`,
`weekly-temporal-provider` (as-of week safety), `weekly-isolation` (provider ≠ manager),
`weekly-schedule`. These are the regression floor.

## D. Proposed smallest defensible candidate model

**Architecture (dependency direction per §32):**
```
Phase 3 FI artifact (frozen)
   └─ lib/football-intel/ read adapter  (exists)
        └─ lib/weekly/start-sit-fi/          NEW — deterministic FI→decision translation
             ├─ reads output_class + predictive_status, routes eligibility
             ├─ applies FROZEN learned coefficients (from R) — no hand-tuned multipliers
             └─ emits { expected_adj, floor_adj, ceiling_adj, confidence_mod, reason_codes[] }
        └─ shadow path in buildWeeklyIntelligence: BASELINE lineup + FI-CANDIDATE lineup + diff
   (buildOptimalLineup / maxSlotMatching UNCHANGED — FI adjusts the projection *fed in*,
    legality + optimization stay exactly as they are)

analysis/football_intel_startsit/            NEW R training + eval (own model version)
   ├─ build_decision_dataset.R   chronology-safe (season,week,player,pos,baseline,FI as-of,actual)
   ├─ train.R                    per-position walk-forward: actual ~ baseline + FI_family_k
   │                             ridge / isotonic on interactions; bootstrap CIs; ablation
   ├─ backtest.R                 pairwise start/sit decision quality + reversal analysis
   └─ publish -> lib/weekly/data/start_sit_model.json (+ feature_status.csv, validation.csv, manifest.json)
```

**v1 model form (conservative — §9):**
`adjusted_projection = baseline_projection + Σ_family  β_{family,position} · confidence_weight · FI_signal_{family}`
where every `β` is **learned by chronology-safe walk-forward regression of actual points on
`baseline + FI`**, retained only if it adds out-of-sample decision value (§13, §37). If a
family's evidence supports only ordering, its effect is **tie-break only** (applied as a small
bounded nudge that can only change the pick when `|baseline_edge| < τ`, τ learned). Bounds:
total FI adjustment capped at a learned per-position maximum (default proposal: ≤ 15% of the
baseline projection, ≤ the amount that flips only "coin-flip"/"close" bucket decisions).

**Confidence weighting (§10):** `confidence_weight = {HIGH:1.0, MEDIUM:0.5, LOW:0.2,
INSUFFICIENT_SAMPLE:0}` × `{prior-dominated: ×0.6}` — monotone, invariant-tested.

**Modes (§6):** v1 certifies **MAX_EXPECTED** with the FI-adjusted projection.
`HIGH_CEILING` / `HIGH_FLOOR` become available *only if* the FI floor/ceiling adjustments
validate (they run over the same Hungarian optimizer with `ceiling_points` / `floor_points` as
the weight). `MAX_WIN_PROBABILITY` and `LATE_SWAP_SAFE`: **capability-stated honestly** — the
win-prob path has no covariance model and `matchup.ts` is post-hoc; Phase 4 will not manufacture
one. `LATE_SWAP_SAFE` is a whole-lineup slot-placement concern tested separately (§28) but not
a new optimizer objective in v1.

**Model identity:** `start_sit_model_version` (e.g. `ri-startsit-2026.1`), distinct from
`football_intelligence_version` and `baseline_projection_version`; a recommendation is
reproducible from all three + roster + scoring.

## E. Major risks

| Risk | Mitigation in the plan |
| --- | --- |
| **Double counting** (RotoWire weekly already prices matchup/role) | Every family classified NOVEL/PARTIAL/DUPLICATIVE (§B); the regression trains on `actual ~ baseline + FI`, so a `β` is retained only for **incremental** value *after* baseline. A family strong in isolation but 0 incremental → DROP or DESCRIPTIVE. |
| **Baseline reconstruction** (Sleeper historical projections may drift through the week) | Run **two baselines** — Sleeper historical + a fully-clean trailing-PPG control; report both; certify against the stricter. Document the limitation, do not fabricate. |
| **Lookahead** | FI via Phase 3's existing walk-forward `build_snapshot.R <season> <week>` + `throughWeek(source)`; baseline from `/projections/{season}/{week}`; actuals last. Explicit leakage audit in the report (§36). |
| **Overfitting** | Small feature set; per-position ridge with bootstrap CIs; walk-forward (never tune prior weeks on future); nested validation for τ and caps; ablation must show stability across folds. |
| **Excessive reversals** (weak signal benching an obvious start) | Tie-break gate (`|baseline_edge| < τ`); hard bound on total adjustment; adversarial audit case set (§31); "protect obvious starts" invariants (§20, §30); reversal analysis is a first-class report section (§19). |
| **Position heterogeneity** | Train + certify **per position**; v1 may certify only QB/RB/WR and leave TE/K/DST as `DEFER`/existing-model (§17). |
| **Regressing the shared optimizer / trade engine** | `buildOptimalLineup` + `maxSlotMatching` **untouched**; FI adjusts the `WeeklyProjection` fed to it; full `test/weekly-*` + `test/trade-*` regression is a gate. |
| **Phase 3 contract defect surfacing** | Document, isolate, do **not** patch Phase 3; stop for review if material (§1). |
| **FI is prior-season (2025) for live 2026 weeks** | Correct as a *preseason prior*, but confidence down-weighted while `through_week` of the current season is low; freshness fields exposed (§23); the translation layer treats a stale-season snapshot as reduced confidence, not as current. |
